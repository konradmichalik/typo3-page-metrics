The Module layout is what draws the docheader around this, so the period switch and the bookmark the controller registers have somewhere to appear. Without it a module template renders its own body and nothing else. Keeps the page tree and this module pointing at the same page: the tree writes the selected uid into ModuleStateStorage, and a module that does not update it sends the reader back to a different page the next time they switch modules. The same handshake the info module does.
Prose, not a tooltip. The reason to build a module at all is room for explanation, and putting it back behind a hover would be the same mistake in a new place.

One block per metric rather than one row: the page-header tile keeps seven qualifying figures, a breakdown and a description behind a hover, which is the right trade on a strip of tiles above somebody's content and the wrong one here. This view exists because there is room, so the figures that explain a number are printed beside it, under the same icon the tile carries, and an editor who saw something in the popover can find it again. Not a wide table: seven figures as seven columns is a horizontal scroll on every backend narrower than a desktop, and a column header cannot carry the sentence each figure needs.
